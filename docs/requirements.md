# RUN TERRITORY 요구사항 분석

## 1. 프로젝트 목표

RUN TERRITORY는 사용자가 실제 러닝을 통해 GPS 경로를 기록하고, 폐곡선으로 만든 면적을 영토로 등록하는 위치 기반 러닝 게임이다.

사용자는 러닝을 통해 포인트를 얻고, 포인트로 캐릭터 뽑기와 강화를 진행하며, 점령 면적과 누적 거리 랭킹을 통해 지속적인 참여를 유도한다.

---

## 2. 핵심 기능 요약

1. Firebase 기반 로그인/회원가입
2. GPS 러닝 경로 기록
3. 폐곡선 완성 시 면적 계산 및 영토 등록
4. 러닝 결과에 따른 포인트 지급
5. 포인트 기반 캐릭터 뽑기 및 강화
6. 영토 침략 및 점령률 변화
7. 영토 자연 감소
8. 면적/거리 랭킹 제공

---

## 3. 사용자 흐름

1. 사용자는 Firebase Auth로 로그인 또는 회원가입한다.
2. 앱은 Firebase ID Token을 서버에 전달한다.
3. 서버는 토큰을 검증하고 사용자 정보를 생성 또는 조회한다.
4. 사용자는 러닝을 시작하고 GPS 경로를 기록한다.
5. 러닝 종료 시 앱은 경로, 거리, 시작 시각을 서버에 전송한다.
6. 서버는 폐곡선 여부, 면적, 포인트를 계산한다.
7. 조건을 만족하면 영토를 등록한다.
8. 사용자는 직접 러닝 보상으로 대표 캐릭터 경험치와 소량의 가챠 재화를 얻는다.
9. 사용자는 획득 재화로 캐릭터를 뽑거나 강화한다.
10. 사용자는 영토와 랭킹을 확인한다.

---

## 4. 기능별 요구사항

### 4.1 인증 / 사용자

- 사용자는 Firebase Auth를 통해 회원가입할 수 있어야 한다.
- 사용자는 Firebase Auth를 통해 로그인할 수 있어야 한다.
- 서버는 Firebase ID Token을 검증할 수 있어야 한다.
- 최초 로그인 사용자는 `users` 테이블에 자동 생성되어야 한다.
- 최초 로그인 사용자는 기본 캐릭터 1개를 지급받아야 한다.
  - 지급 대상은 common 등급의 공격형/수비형/버프형 캐릭터 중 랜덤 1개다.
- 사용자 닉네임은 필수값이며, 기본값 정책이 필요하다.
  - Firebase `displayName` 우선
  - 없으면 이메일 앞부분 사용
  - Firebase 이메일 정보가 없는 토큰은 인증 실패 처리

### 4.2 GPS 러닝 / 영토

- 사용자는 러닝을 시작하고 종료할 수 있어야 한다.
- 앱은 러닝 중 GPS 좌표를 수집할 수 있어야 한다.
- 앱은 포그라운드 러닝 화면에서 GPS 좌표를 수집한다.
- 백그라운드 GPS는 `react-native-background-actions` 기반으로 처리한다.
- `expo-location` 기반 백그라운드 GPS 추적은 사용하지 않는다.
- 러닝 종료 시 앱은 서버에 GPS 경로를 전송해야 한다.
- 서버는 러닝 경로를 저장할 수 있어야 한다.
- 서버는 폐곡선이 완성된 경우 면적을 계산할 수 있어야 한다.
- 계산된 면적은 영토로 등록될 수 있어야 한다.
- 하나의 지도에서 모든 사용자의 영토를 표시할 수 있어야 한다.
- 영토는 개별 ID를 가지며, 캐릭터 배치와 침략 대상 지정에 사용된다.
- 사용자는 자신이 보유한 영토의 이름을 수정할 수 있어야 한다.
- 메뉴의 내 영토 관리 화면에서 사용자는 본인이 보유한 영토 목록을 확인할 수 있어야 한다.
- 지도에서 내 영토와 다른 사용자의 영토를 시각적으로 구분할 수 있어야 한다.
- 지도 위 점령 영토에는 보유자 이름, 면적 등 기본 정보가 표시될 수 있어야 한다.
- 배치 캐릭터 정보는 영토 상세 조회에서 확인할 수 있어야 한다.
- 점령된 영토를 선택하면 영토 상세 화면을 열 수 있어야 한다.
- 영토 상세 화면에는 보유자 이름, 배치 캐릭터의 스탯 등 상세 정보가 표시되어야 한다.

#### 폐곡선 판단 기준

- 좌표는 `{ lat: number, lng: number }` 형태를 사용한다.
- 좌표가 3개 이상이어야 한다.
- 시작점과 종료점의 거리가 50m 이내이면 폐곡선으로 판단한다.
- 폐곡선이 아니면 러닝 기록은 저장하되 영토는 생성하지 않는다.

### 4.3 포인트 계산

러닝 경로 기반 이동 거리와 평균 페이스를 기준으로 포인트를 지급한다.

폐곡선을 만들지 못한 러닝은 즉시 완주 보상이 더 높을 수 있다. 폐곡선 영토를 만든 사용자는 이후 주기적 포인트 획득이 가능하므로 장기 보상이 더 높아지는 구조를 전제로 한다.

보상을 위해 러닝을 짧게 끊는 행동을 줄이기 위해, 끊지 않고 오래 달린 러닝의 보상은 추가 보정으로 증가할 수 있다.

포인트 공식:

```ts
const basePoints = Math.floor(distanceKm * 100 * paceMultiplier * distanceMultiplier);
const earnedPoints = isClosedLoop ? basePoints : Math.floor(basePoints * 1.3);
```

- `distanceKm`: 서버가 `path` 좌표로 계산한 이동 거리
- `paceMultiplier`: 서버 계산 평균 페이스 기준 보정값
- `distanceMultiplier`: 장거리 러닝 보정값. 현재 구현 기준 `Math.min(1.1 ** distanceKm, 3.0)`
- 폐곡선을 만들지 못한 러닝은 영토를 생성하지 않는 대신 즉시 보상에 1.3배를 적용한다.
- 폐곡선으로 생성된 영토는 이후 시간당 포인트 수익을 만든다.
  - 시간당 수익은 사용자별 유효 점령 면적 기준으로 지급한다.
  - 유효 점령 면적은 `area_sqm * occupation_rate / 100`으로 계산한다.
  - 기본 수익은 현재 구현 기준 `Math.floor(유효 점령 면적 합계 / 1000)` 포인트를 매시간 지급한다.
  - 버프형 캐릭터가 영토에 배치된 경우 해당 영토의 수익 기여분에 포인트 효율 배율을 곱한다.
  - 포인트 효율 배율은 `Math.min(base_point_rate + (point_lv - 1) * 0.05, 2.0)`을 사용한다.
  - 수비형 캐릭터 또는 미배치 영토는 배율 `1.0`을 사용하므로 기존 수익과 동일하다.

| 평균 페이스 | 보정값 |
|---|---:|
| 3분/km 미만 | 무효(0) |
| 3~4분/km | x1.2 |
| 4~5분/km | x1.0 |
| 5~7분/km | x0.8 |
| 7~8분/km | x0.6 |
| 8분/km 초과 | 무효(0) |

앱에서 예상 포인트를 표시하는 경우 서버와 동일한 기준을 사용해야 한다.

### 4.4 캐릭터 / 가챠

- 사용자는 포인트로 캐릭터를 뽑을 수 있어야 한다.
- 사용자는 보유 캐릭터 목록을 조회할 수 있어야 한다.
- 캐릭터 최대 보유 개수는 30개다.
- 캐릭터 보유 페이지에서는 등급별, 능력 타입별(공격/수비/버프) 정렬을 제공할 수 있어야 한다.
- 캐릭터 보유 페이지에서 캐릭터를 선택하면 캐릭터 상세 화면을 볼 수 있어야 한다.
- 캐릭터 상세 화면에는 현재 구현된 공격/방어/포인트 효율 스탯 정보를 우선 표시한다.
- 속도 스탯은 사용하지 않는다.
- 캐릭터 스탯은 공격, 방어, 포인트 효율 3종으로 정리한다.
- 공격 스탯은 침략 시 공격형 캐릭터의 공격력 계산에 사용한다.
- 방어 스탯은 영토에 배치된 수비형 캐릭터의 방어력 계산에 사용한다.
- 포인트 효율 스탯은 영토에 배치된 버프형 캐릭터의 시간당 포인트 수익 증가 계산에 사용한다.
- 캐릭터 이미지, 레벨, 경험치 표시는 보유 캐릭터 상세 화면과 API 응답에 포함한다.
- 사용자는 스탯 포인트를 사용해 캐릭터의 공격/방어/포인트 효율 스탯을 강화할 수 있어야 한다.
- 사용자는 캐릭터를 분해해 스탯 포인트를 획득할 수 있어야 한다.
- 캐릭터 분해 시 획득 스탯 포인트는 등급에 따라 1~4개를 지급한다.
- 캐릭터 분해로 획득한 스탯 포인트는 캐릭터 공격/방어/포인트 효율 스탯 강화 비용으로 사용한다.
- 캐릭터 보유 페이지에는 분해 버튼이 있어야 하며, 분해 버튼을 누르면 원하는 캐릭터들을 선택해 일괄 분해할 수 있어야 한다.
- 캐릭터 분해는 한 번에 최대 29개까지 가능하며, 분해 후에도 최소 1개의 캐릭터는 보유해야 한다.
- 캐릭터 등급은 `common`, `rare`, `epic`, `legendary`를 사용한다.
- 캐릭터 타입은 `attack`, `defense`, `buff`를 사용한다.
- 공격형/수비형/버프형은 같은 스탯 구조를 공유하지만, 타입별 주요 역할은 각각 침략, 방어, 수익 증가로 구분한다.
- 점령형 캐릭터 타입은 사용하지 않는다.
- 천장 보장 시스템은 사용하지 않는다.
- 가챠 비용은 현재 구현 기준 1회 100 포인트, 10회 900 포인트를 사용한다.
- 가챠 확률은 현재 구현 기준 common 60%, rare 30%, epic 9%, legendary 1%를 사용한다.
- 캐릭터 강화 비용은 현재 구현 기준 스탯 포인트 1개를 사용한다.
- 사용자는 대표 캐릭터를 설정할 수 있어야 한다. 직접 러닝 보상 경험치는 대표 캐릭터에 지급한다.
- 직접 러닝 보상으로 대표 캐릭터 경험치와 소량의 가챠 재화를 지급한다.
- 캐릭터 경험치가 기준치를 넘으면 캐릭터 레벨이 상승하고, 레벨에 따라 캐릭터 능력치가 성장한다.
- 대표 캐릭터 경험치는 러닝 거리(`distanceKm`)가 0보다 클 때 `Math.max(1, Math.floor(distanceKm * 20))`만큼 지급한다.
- 캐릭터 다음 레벨 필요 경험치는 `100 + (현재 레벨 - 1) * 50`을 사용한다.
- 캐릭터 최대 레벨은 common 10, rare 15, epic 20, legendary 30을 사용한다. 현재 스탯 레벨 상한도 동일한 등급별 수치를 사용한다.
- 캐릭터 레벨업 시 타입별 주 스탯이 1 증가한다.
  - 공격형: 공격 스탯 +1
  - 수비형: 방어 스탯 +1
  - 버프형: 포인트 효율 스탯 +1
  - 주 스탯은 등급별 최대 레벨을 초과하지 않는다.
- 수비형/버프형 캐릭터는 사용자 영토에 배치될 수 있다.
- 버프형 캐릭터가 배치된 영토는 포인트 효율 스탯에 따른 시간당 포인트 수익 배율을 적용할 수 있다.
- 내 영토 관리와 홈 지도 영토 상세 화면에서는 영토별 시간당 예상 수익, 기준 수익, 버프 배율을 확인할 수 있어야 한다.
- 캐릭터 배치는 홈 지도에서 내 영토를 선택해 진행할 수 있어야 한다.
- 캐릭터 배치는 메뉴의 내 영토 관리 화면에서도 진행할 수 있어야 한다.
- 내 영토 관리 화면은 영토 개수, 총 면적, 각 영토의 면적, 점령률, 최근 활동 시간을 표시해야 한다.
- 사용자는 내 영토 관리 화면에서 영토 이름을 수정하거나 삭제할 수 있어야 한다.
- 캐릭터 배치 후보 목록은 캐릭터 이미지, 등급, 타입, 방어/포인트 효율 스탯 정보를 표시해야 한다.
- 캐릭터 배치 후보 목록은 최근/등급/타입 정렬을 제공하고, 타입 정렬 시 수비형/버프형 필터를 제공해야 한다.
- 공격형 캐릭터는 영토 배치 후보에 포함하지 않는다.
- 캐릭터 배치는 `user_characters.deployed_territory_id`로 특정 영토를 지정한다.
- 하나의 영토에는 하나의 수비형/버프형 캐릭터만 배치할 수 있다.
- 배치 여부는 `deployed_territory_id IS NOT NULL`로 판단하며 별도 `is_deployed` 컬럼은 사용하지 않는다.

### 4.5 영토 침략

- 사용자는 다른 사용자의 영토를 침략할 수 있어야 한다.
- 침략 시 사용할 공격형 사용자 캐릭터를 지정해야 한다.
- 침략 판정에는 현재 사용자의 러닝 로그를 사용해야 한다.
- 침략자는 대상 점령 영토 면적의 최소 30% 이상을 직접 러닝으로 지나가야 침략 전투를 시도할 수 있다.
- 서버는 `POST /territories/:id/attack` 처리 중 러닝 로그의 GPS 경로와 대상 영토의 겹친 면적을 계산해 침략 가능 여부를 판단해야 한다.
- 침략 조건을 만족하면 공격 캐릭터와 대상 영토에 배치된 방어 캐릭터를 기준으로 침략 성공 여부를 계산한다.
- 침략 성공 시 러닝 경로와 대상 영토가 실제로 겹친 폴리곤 영역을 공격자 소유로 이전해야 한다.
- 획득 면적은 점령률 감소분 환산값이 아니라 실제 겹침 폴리곤 면적으로 계산해야 한다.
- 침략 성공 시 방어자 영토 폴리곤은 실제 겹침 폴리곤을 제외한 형태로 갱신한다.
- 공격자 영토는 획득한 겹침 폴리곤을 기존 공격자 영토와 `union` 하여 병합한다.
- 침략 성공 시 획득 폴리곤은 공격자 기존 영토와 인접한 것으로 간주하며, 별도 새 영토 생성 분기는 두지 않는다.
- 방어자 영토의 `coordinates`, `area_sqm`, `center_lat`, `center_lng`는 차집합 결과 기준으로 재계산한다.
- 공격자 영토의 `coordinates`, `area_sqm`, `center_lat`, `center_lng`는 병합 결과 기준으로 재계산한다.
- 차집합 결과 방어자 영토 면적이 0이면 해당 영토는 `area_sqm = 0`, `occupation_rate = 0`으로 중립화하고 DB 레코드는 보존한다.
- 0% 중립화 영토는 지도/목록/랭킹/침략 대상 조회에서 `area_sqm > 0`과 `occupation_rate > 0` 조건으로 제외한다.
- 차집합 결과가 `MultiPolygon`이면 1차 스코프 확정 정책으로 가장 큰 조각만 보존하고 나머지 조각은 삭제해 단일 폴리곤 구조를 유지한다.
- 지도에서는 변경된 방어자/공격자 영토 폴리곤이 즉시 반영되어 침략 결과가 드러나야 한다.
- 침략 실패 시 겹침 후보 영역은 소유권 이전 없이 그대로 유지된다.
- 점령률은 소유 면적을 직접 나타내는 값이 아니라 방어력 보정과 자연 감소 관리를 위한 별도 상태값으로 유지한다.
- 점령률은 침략 시 방어력 보정, 시간당 포인트 수입, 자연 감소, 랭킹 필터에 사용한다.
- 획득 면적 계산은 점령률 감소분 환산값을 사용하지 않고 실제 겹침 폴리곤 면적을 사용한다.
- 침략 전투 우세 여부는 겹침 폴리곤이 존재하고 공격력이 보정 방어력을 초과하는지로 판단한다.
- 실제 소유권 이전 여부는 겹침 폴리곤이 존재하고 점령률이 실제로 감소하는지로 판단한다.
- 점령률 감소는 침략 결과의 참고 상태값이며, 폴리곤 이전 면적과 직접 연결하지 않는다.
- 대상 점령 영토에 포함되지 않은 새 면적은 일반 러닝 영토 생성 규칙에 따라 처리한다.
- 서버는 공격/방어 능력치와 배치 캐릭터 효과를 기준으로 침략 결과를 계산해야 한다.
- 공격력은 `attackerCharacter.character.base_attack + (attackerCharacter.attack_lv - 1) * 5`로 계산한다.
- 방어력은 대상 영토에 배치된 수비형 캐릭터들의 `defender.character.base_defense + (defender.defense_lv - 1) * 5` 합으로 계산한다.
- 실제 방어력은 `defensePower * (occupation_rate / 100)`로 보정한다.
- 최종 피해량은 `Math.max(0, attackPower - defenseWithRate)`로 계산한다.
- 침략 후 점령률은 `Math.max(0, occupation_rate - Math.floor(damage))`로 계산하되, 소유권 이전 면적 계산에는 사용하지 않는다.
- 침략 성공 응답의 `success`는 실제 겹침 폴리곤이 존재하고 `Math.floor(damage) > 0`이라 점령률이 감소한 경우에만 `true`로 본다.
- 공격자가 획득한 폴리곤은 기존 공격자 영토와 병합한다.
- 하루 침략 가능 횟수는 5회이며, `attack_logs`의 공격자/날짜 기준 카운트로 계산한다.
- 새로 생성된 영토는 생성 시각 기준 5분 동안 침략 보호 시간을 가진다.
- 침략 응답에는 다음 침략 가능 시각과 당일 남은 침략 횟수를 포함한다.
- 침략 로그가 저장되면 성공/실패와 관계없이 해당 사용자에게 5분 침략 쿨타임이 적용된다.
- 쿨타임 중 침략 요청은 400으로 거부하며, 침략 처리 응답의 `nextAttackAvailableAt`은 다음 침략 가능 시각을 반환한다.
- 자기 영토 침략, 공격형이 아닌 캐릭터 사용, 하루 5회 초과, 30% 미만 겹침은 400으로 거부한다.
- 대상 영토, 현재 사용자의 러닝 로그, 현재 사용자의 보유 캐릭터가 없으면 404로 거부한다.

### 4.6 영토 자연 감소

- 일정 기간 활동이 없으면 영토 점령률이 감소해야 한다.
- 점령률이 0이 되면 영토는 중립화되어야 한다.
- 점령률은 시간이 지나면 반드시 감소한다.
- ~~사용자가 직접 러닝으로 해당 영토 활동 조건을 충족하면 `last_active_at`을 갱신해 자연 감소 기준 시점을 늦추는 방식을 우선 적용한다.~~ (1차 스코프 제외)
- ~~영토 활동 조건은 러닝 경로와 해당 영토의 겹침 비율 등을 기준으로 후속 구현에서 확정한다.~~ (1차 스코프 제외)
- 자연 감소 스케줄러는 매일 UTC 00:00(KST 09:00)에 실행된다.
- `last_active_at` 기준 4일 이상 비활동 영토는 점령률 75%, 8일 이상은 50%, 15일 이상은 25%, 22일 이상은 0%로 낮춘다.
- 자연 감소는 `area_sqm > 0`인 영토 중 현재 점령률이 목표 점령률보다 높은 영토에만 적용한다.
- 자연 감소 업데이트는 `last_active_at`을 변경하지 않는다.
- 영토에 배치된 수비형 캐릭터는 방어 레벨에 따라 자연 감소 기준일을 최대 3일 늦춘다.
- 수비형 자연 감소 유예일은 `Math.min(Math.floor((defenseLv - 1) / 5), 3)`으로 계산한다.
  - `defenseLv`는 API/요구사항 표기이며, 서버 내부 DB 컬럼 `defense_lv`와 같은 방어 레벨 값을 의미한다.
  - `defenseLv` 1~5: 추가 유예 없음
  - `defenseLv` 6~10: 기준일 +1일
  - `defenseLv` 11~15: 기준일 +2일
  - `defenseLv` 16 이상: 기준일 +3일
- 현재 자연 감소 유예일은 서버 스케줄러 내부 계산에만 사용하며 별도 API 응답 필드로 제공하지 않는다.
- 버프형 캐릭터는 자연 감소에 관여하지 않고 시간당 포인트 수익 증가에만 사용한다.
- 포인트 수익 스케줄러의 버프형 캐릭터 연동 공식은 4.3의 시간당 수익 공식을 따른다.
