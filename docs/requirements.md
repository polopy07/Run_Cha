# RUN TERRITORY 요구사항 분석

## 1. 프로젝트 목표

RUN TERRITORY는 사용자가 실제 러닝을 통해 GPS 경로를 기록하고, 폐곡선으로 만든 면적을 영토로 등록하는 위치 기반 러닝 게임이다.

사용자는 러닝을 통해 포인트를 얻고, 포인트로 캐릭터 뽑기와 강화를 진행하며, 점령 면적과 누적 거리 랭킹을 통해 지속적인 참여를 유도한다.

---

## 2. 핵심 기능 요약

1. Firebase 기반 로그인/회원가입
2. GPS 러닝 경로 기록
3. 폐곡선 완성 시 면적 계산 및 영토 등록
4. 러닝 결과에 따른 포인트 지급
5. 포인트 기반 캐릭터 뽑기 및 강화
6. 영토 침략 및 점령률 변화
7. 영토 자연 감소
8. 면적/거리 랭킹 제공

---

## 3. 사용자 흐름

1. 사용자는 Firebase Auth로 로그인 또는 회원가입한다.
2. 앱은 Firebase ID Token을 서버에 전달한다.
3. 서버는 토큰을 검증하고 사용자 정보를 생성 또는 조회한다.
4. 사용자는 러닝을 시작하고 GPS 경로를 기록한다.
5. 러닝 종료 시 앱은 경로, 거리, 평균 페이스를 서버에 전송한다.
6. 서버는 폐곡선 여부, 면적, 포인트를 계산한다.
7. 조건을 만족하면 영토를 등록한다.
8. 사용자는 획득 포인트로 캐릭터를 뽑거나 강화한다.
9. 사용자는 영토와 랭킹을 확인한다.

---

## 4. 기능별 요구사항

### 4.1 인증 / 사용자

- 사용자는 Firebase Auth를 통해 회원가입할 수 있어야 한다.
- 사용자는 Firebase Auth를 통해 로그인할 수 있어야 한다.
- 서버는 Firebase ID Token을 검증할 수 있어야 한다.
- 최초 로그인 사용자는 `users` 테이블에 자동 생성되어야 한다.
- 사용자 닉네임은 필수값이며, 기본값 정책이 필요하다.
  - Firebase `displayName` 우선
  - 없으면 이메일 앞부분 사용
  - 이메일도 없으면 `user` 사용

### 4.2 GPS 러닝 / 영토

- 사용자는 러닝을 시작하고 종료할 수 있어야 한다.
- 앱은 러닝 중 GPS 좌표를 수집할 수 있어야 한다.
- 러닝 종료 시 앱은 서버에 GPS 경로를 전송해야 한다.
- 서버는 러닝 경로를 저장할 수 있어야 한다.
- 서버는 폐곡선이 완성된 경우 면적을 계산할 수 있어야 한다.
- 계산된 면적은 영토로 등록될 수 있어야 한다.

#### 폐곡선 판단 기준

- 좌표는 `{ lat: number, lng: number }` 형태를 사용한다.
- 좌표가 3개 이상이어야 한다.
- 시작점과 종료점의 거리가 50m 이내이면 폐곡선으로 판단한다.
- 폐곡선이 아니면 러닝 기록은 저장하되 영토는 생성하지 않는다.

### 4.3 포인트 계산

러닝으로 생성된 면적과 평균 페이스를 기준으로 포인트를 지급한다.

포인트 공식:

```ts
Math.floor(areaSqm / 100 * paceMultiplier)
```

| 평균 페이스 | 보정값 |
|---|---:|
| 3분/km 미만 | 무효(0) |
| 3~4분/km | x1.2 |
| 4~5분/km | x1.0 |
| 5~7분/km | x0.8 |
| 7~8분/km | x0.6 |
| 8분/km 초과 | 무효(0) |

앱에서 예상 포인트를 표시하는 경우 서버와 동일한 기준을 사용해야 한다.

### 4.4 캐릭터 / 가챠

- 사용자는 포인트로 캐릭터를 뽑을 수 있어야 한다.
- 사용자는 보유 캐릭터 목록을 조회할 수 있어야 한다.
- 사용자는 포인트를 사용해 캐릭터 스탯을 강화할 수 있어야 한다.
- 캐릭터 등급은 `common`, `rare`, `epic`, `legendary`를 사용한다.
- 캐릭터 타입은 `attack`, `defense`, `territory`, `buff`를 사용한다.
- 100회 뽑기 천장 보장 여부를 기록할 수 있어야 한다.

### 4.5 영토 침략

- 사용자는 다른 사용자의 영토를 침략할 수 있어야 한다.
- 침략 시 사용할 캐릭터를 지정해야 한다.
- 서버는 공격/방어 능력치와 점령률을 기준으로 침략 결과를 계산해야 한다.
- 침략 API의 요청 필드는 구현 전 확정이 필요하다.

### 4.6 영토 자연 감소

- 일정 기간 활동이 없으면 영토 점령률이 감소해야 한다.
- 점령률이 0이 되면 영토는 중립화되어야 한다.
- 자연 감소 주기와 감소량은 추후 확정한다.

### 4.7 랭킹

- 사용자는 보유 면적 랭킹을 확인할 수 있어야 한다.
- 사용자는 누적 러닝 거리 랭킹을 확인할 수 있어야 한다.

---

## 5. 비기능 요구사항

- `.env`, Firebase Admin 서비스 키, API Key는 GitHub에 커밋하지 않는다.
- 앱과 서버는 동일한 API 명세를 기준으로 개발한다.
- 서버 API는 DTO 기반으로 요청 데이터를 검증한다.
- 앱 연동 전 요청/응답 타입을 명확히 문서화한다.
- 공통 에러 응답 형식을 통일한다.
